# 教师来源与迁移边界

来源：同作者项目 [TRGoChessC](https://github.com/RickT34/TRGoChessC) 的棋型表与评分思路。

- `AIPlayer.c` 的 `AIPatterns_Default`（16 类棋型）和 `AIPatternPowers_Default_G11` 原样保留数字与含义。
- `GetPatternTrie` 的镜像补全、己方系数 2、对方防守系数 2.079848，以及 `TrieQuery` 的重叠命中累加语义，由独立 Python 字符串参考实现核对。
- 沿四条线增量更新局面分数，候选区域仍沿八个方向延伸两格。

搜索是本项目重新实现的适配版本，不是对原二进制逐步完全等价的封装：

1. 原棋盘固定 15×15，`unsigned char Point` 不能容纳 19×19；现在使用普通整数索引，支持 5–25。
2. 原 `Minimax` 在 `dep == 0` 分支只写 `ret`，后面却读取未初始化的 `power`。新版本独立检查合法五连终局，不依赖加权棋型分数阈值代替规则。
3. 使用固定根玩家视角的 max/min。G11 敌我系数并不反对称，不直接把该评分当作可任意翻转视角的 Negamax 评分。
4. 原置换记录缺少搜索深度与精确/上界/下界类型，新表保存这些信息，容量固定，不越界分配。每次根搜索独立建表。
5. 新版本迭代加深，提供节点预算与候选宽度。节点预算中断时返回最后一个完整完成的深度；若第一层也没完成，返回排序候选，并明确报告完成深度 0。先找一步成五，再强制挡对方一步成五，这些动作不会被宽度截断。
6. 每个局面的搜索串行；OpenMP 只并行独立局面。不存在原根节点并行中对共享 `rate` 的未同步读取，也没有跨棋局共享可变搜索数据。

`width: 0` 禁用候选宽度限制，`nodes: 0` 禁用节点预算，仍只搜索邻近候选。它不是完备解算器。源码指纹写入数据集配置，改变教师后应创建新的数据集，以免实验来源混淆。

测试覆盖两方四方向的一步成五与防守、15/19 棋盘评分对照、小棋盘两步穷举对照、多线程/单线程结果一致，以及终局和错误输入。

`teacher_policy_batch` 额外提供分布蒸馏所需的根候选评分：各候选使用完整搜索窗口，并只发布所有候选共同完成的深度。节点预算覆盖整个局面；不足以完成第一轮时返回所有候选的静态评分并标记深度 0。根节点保留所有立即获胜点。评分只在原有候选剪枝下成立，不代表全合法动作的完备 minimax 值。原 `teacher_batch` 的单落点接口保留。
